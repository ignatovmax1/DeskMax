## Ограничения и оставшаяся работа

- Передача экрана, ввод мыши/клавиатуры, WebRTC и Android-клиент отсутствуют. Это координационный прототип, не готовое приложение удалённого управления.
- Регистрации и доверие хранятся в памяти сервера; ID клиента меняется при повторной регистрации. Нужны постоянная БД и защищённое хранение клиентского секрета.
- Журнал отображает события текущего запуска и не является постоянным серверным аудитом.
- Управление доверенными устройствами доступно через API, но отдельного интерфейса управления доверием пока нет.
- Визуальная проверка на разных DPI, экранных разрешениях и полный автоматизированный проход по WPF-контролам не выполнены. Подтверждён запуск окна, а не исчерпывающий UI-тест.
- Загрузка опубликованного установщика, его запуск, Docker/Coturn и нагрузочные проверки не выполнялись.
- Шестизначные коды могут совпасть: сервер безопасно отклоняет неоднозначный код. Для масштабирования нужен адресный запрос по ID и коду.
- Нет ограничений регистрации и постоянного хранения; API не следует выставлять в открытый интернет как готовую production-систему.

## Локальный запуск

В PowerShell задайте случайный ключ в текущем процессе и запустите сервер:

```powershell
$env:Security__RotatingCodeKey = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
& 'C:\Program Files\dotnet\dotnet.exe' run --project src/DeskMax.Server --launch-profile http
```

В другом терминале:

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --project src/DeskMax.Windows
```

Адрес клиента по умолчанию: http://localhost:5186. Для Docker используйте в настройках http://localhost:8080. При смене ключа и перезапуске сервера его состояние теряется.
