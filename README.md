# DeskMax

Клиенты по умолчанию подключаются к `https://anydesk.familyserver.su/`. В Windows адрес можно изменить в настройках. Исходники следующего выпуска — 0.4.3; опубликованный стабильный выпуск проверяйте в GitHub Releases.

Удалённый доступ для Windows 10/11 и Android 8.0+. Windows открывается с тёмной темой; светлую можно включить в настройках. Выбор сохраняется для следующего запуска. Android использует тёмный интерфейс.

Реализованы WPF-клиент, захват основного монитора, просмотр удалённого экрана, мышь, прокрутка, клавиатура, запрос подтверждения владельца и остановка доступа. Кадры JPEG передаются через WebSocket-сервер: до 10 кадров/с, до 1280 пикселей по длинной стороне. Ввод применяется через Windows SendInput.

Владелец видит окно трансляции и может остановить сеанс кнопкой или Ctrl+Alt+F12. При закрытии, потере соединения, отзыве или истечении срока доступ прекращается, удалённо удерживаемые клавиши и кнопки отпускаются. Обычный запрос действует 2 минуты, разрешённый сеанс — максимум 1 час.

Транспорт защищён HTTPS/WSS. Это передача через сервер, без сквозного шифрования и без WebRTC: сервер имеет доступ к содержимому кадров. Регистрации пока хранятся в памяти, ID меняется при повторной регистрации. Звук, файлы, буфер обмена, дополнительные мониторы и постоянный доступ без присутствия владельца пока не реализованы. Windows ограничивает ввод в приложения с более высокими правами и защищённый рабочий стол UAC.

Android может просматривать удалённый экран и отправлять касания, прокрутку, клавиши и Unicode-текст. Передача экрана телефона требует подтверждения владельца и системного разрешения на захват для каждого сеанса. Во время передачи работает foreground-уведомление с остановкой. Для управления телефоном владелец отдельно включает DeskMax в системных настройках специальных возможностей; без этого доступен просмотр. Некоторые приложения и защищённые поля запрещают захват или изменение текста. Реальную работу MediaProjection и Accessibility на физическом телефоне необходимо проверить отдельно от серверных и эмуляторных тестов.

## Подключение

1. Запустите одинаковую актуальную версию на обоих устройствах.
2. Владелец передаёт свой временный код. Второй участник вводит его и отправляет запрос.
3. Владелец открывает «Запросы доступа», выбирает запрос, нажимает «Разрешить» и подтверждает передачу экрана и управление.
4. У второго участника открывается экран. Нажмите на изображение для управления мышью и клавиатурой. Галочка управления позволяет оставить только просмотр.
5. Для остановки закройте окно сеанса или нажмите «Завершить сеанс». У владельца также работает Ctrl+Alt+F12, если комбинация не занята другой программой.

## Обновления и Windows-сборки

Канал — **Stable / GitHub Releases**. При запуске Windows-клиент проверяет наличие обновления и показывает кнопку с новой версией. Установка начинается после подтверждения пользователя. Draft и prerelease-релизы не предлагаются. Кнопка «Проверить обновления» выполняет проверку вручную.

Для выпуска измените Windows Version, MyAppVersion установщика, Android versionName и увеличьте versionCode. Сначала дождитесь Android validation (unit tests, lint и API 35 emulator), затем отправьте тег vMAJOR.MINOR.PATCH. Release workflow проверяет версии, собирает обе платформы и публикует стабильный релиз только после успеха обеих сборок. Артефакты: DeskMax.exe, DeskMaxSetup.exe и SHA-256, DeskMax-Android.apk и SHA-256. APK подписывается постоянным ключом из GitHub Secrets; сохраните резервную копию ключа вне репозитория. Пароли сервера и GitHub-токены в клиент не включаются.

Android-кнопка обновления открывает APK из стабильного GitHub Release в браузере. Установку подтверждает пользователь средствами Android; встроенной проверки SHA-256 у Android-клиента пока нет. APK устанавливается вручную с разрешением установки из выбранного источника. Для обновлений должна сохраняться подпись APK.

Windows-клиент проверяет последний GitHub Release кнопкой «Проверить обновления». Он принимает только файл `DeskMaxSetup.exe`, сверяет опубликованный SHA-256 и лишь затем запускает установщик. Workflow `.github/workflows/release.yml` автоматически собирает приложение и установщик при публикации тега `v*`.

Локальные артефакты после сборки:

- `artifacts/app/DeskMax.exe` — самостоятельное приложение;
- `artifacts/installer/DeskMaxSetup.exe` — установщик;
- `artifacts/installer/DeskMaxSetup.exe.sha256` — контрольная сумма.

## Сборка

Android: JDK 17, SDK 35, Gradle wrapper 8.11.1; в каталоге android выполните gradlew.bat testDebugUnitTest lintDebug assembleDebug. Release использует ANDROID_KEYSTORE_PATH, ANDROID_KEYSTORE_PASSWORD, ANDROID_KEY_ALIAS, ANDROID_KEY_PASSWORD. connectedDebugAndroidTest требует запущенного эмулятора или устройства.

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' build DeskMax.slnx
& 'C:\Program Files\dotnet\dotnet.exe' test DeskMax.slnx
```

Интерактивная проверка настоящего захвата и ввода через изолированный локальный сервер:

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' build DeskMax.slnx -c Release
& 'C:\Program Files\dotnet\dotnet.exe' run --project tests/DeskMax.Desktop.Smoke -c Release -- --relay
```

Тест открывает собственное окно, проверяет фокус перед вводом, восстанавливает курсор и останавливает временный сервер. Его запускают явно на разблокированном Windows-рабочем столе. Обычный CI выполняет серверные и протокольные тесты без ввода на рабочий стол.
